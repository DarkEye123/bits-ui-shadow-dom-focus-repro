bits-ui Dialog focus inside a Shadow Root

A modal dialog should do two things with keyboard focus:

  • Trap focus: while it is open, Tab cycles through the dialog's own buttons (First → Second → Close → First) and never reaches the page behind it.
  • Restore focus: when it closes, focus returns to the element that opened it, so a keyboard user continues from there.

Use the keyboard only: Tab to a button, press Enter to open, Tab through the dialog, press Escape to close. In Safari, press Option+Tab instead of Tab (plain Tab moves only between text fields). Open the dialogs with the keyboard, not the mouse: Safari does not focus a clicked button, so after a mouse click it has nothing to restore, even in case 1.

Each case shows where focus went while the dialog was open and after it closed.

Case 1: light DOM (control, works)

Expected and actual
Tab cycles First → Second → Close → First. After Escape, focus is back on the "Open light dialog" button.

Case 2: inside a Shadow Root, trigger inside the root (focus restore broken)

Expected
The same as case 1: after Escape, focus is back on the "Open shadow dialog" button.
Actual (bits-ui 2.19.3)
Tab cycles correctly, but only by accident (see the README). After Escape, nothing is focused (the page body), so the next Tab starts again from the top of the page.

Case 3: inside a Shadow Root, dialog open on mount (focus trap broken)

The button mounts a new Shadow Root at the end of the page whose dialog starts open, like a checkout popup. Nothing focusable comes after it.

Expected
Tab cycles First → Second → Close → First.
Actual (bits-ui 2.19.3)
Chrome and Safari: Tab after Close leaves the dialog (the log shows "nothing (the page body)"). Firefox: Tab after Close stays on Close.
